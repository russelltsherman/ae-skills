## Risks
- The baseline may invoke skill-creator anyway because it shows up in the skill list, which would blur the with/without delta (spec R3). Graders check the order (skill-creator invoked before any file write) and that it was invoked through the Skill tool, not just that it was invoked. The chat summary reports the baseline's behaviour so the operator can judge the delta.
- R4 has no eval case, because skill-creator cannot be removed from a run (spec R4). The stop rule is checked by reading SKILL.md, so a regression in the agent's behaviour would not be caught automatically.
- The description over-triggers on any skill-related task, or under-triggers for spec and plan writing (spec R1). Step 9 uses explicit negative and positive trigger queries.
- skill-creator's viewer changes and makes R8 or R10 wrong or redundant (spec design: why each workaround exists). Step 3 re-checks this before drafting, and the SKILL.md states each reason so a future agent can raise it.
- Case folders and skill-creator's `evals.json` workflow drift apart (spec R6). The SKILL.md says plainly that case folders are the source and how each skill-creator step reads them; `make check` lints the folders.
- skill-creator's default puts cases inside the skill's folder, and the agent follows it while building this skill (spec R6). Proof checks that `skills/policy-skill-authoring/evals` does not exist and that no file names that path.
- Drafts in `hold/` are copied in rather than rebuilt, so the eval evidence no longer matches how the skill was made (spec design: building this skill). Step 2 says nothing is copied, and every iteration runs against the SKILL.md drafted in step 4.
- A workspace gets committed by accident (spec design: eval workspaces). `plugins/workflow/.gitignore` already ignores `skills/*-workspace/` and `evals/*/results/`.
- Workspaces are not in the repo, so the eval evidence lives only on the machine that ran it (spec design: eval workspaces). The chat summaries (R9) and the `run_loop.py` summary (R14) are what the operator keeps; the commit message notes the final iteration's pass rates.
- `make evals` with no `SKILL=` also runs this skill's cases, without tool grants, since it has no `allow-tools` file (spec Out of scope). Those runs may fail; they are not this build's evidence.
- The baseline exemption is read too broadly, and a skill the model can start skips baselines (spec R17, R18). The `model-invoked-skill-runs-baseline` case checks that baselines are still planned. Removing the flag (R18) has no case (operator decision, 2026-11-04); the manual SKILL.md check covers its wording.
- Skipping baselines is taken as permission for reduced mode (spec R21). It has no case (operator decision, 2026-11-04); the manual SKILL.md check covers the reduced-mode wording, and `command-only-skips-baseline` lists only with-skill runs rather than results in chat.
- The policy is advisory only (spec Out of scope), so a session may ignore it. Accepted; enforcement is deferred.
- The README drifts from SKILL.md or the case list (spec R22). It is written last, after the description is final, names SKILL.md as the source of truth, and `make lint-readmes` checks its case list against `evals/policy-skill-authoring/`.
