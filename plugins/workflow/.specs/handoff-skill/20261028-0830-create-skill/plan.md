## Risks
- Recorded histories go stale. A newer Claude Code may resume an old `.jsonl` differently or reject it (spec design: multi-turn cases). Step 3 re-checks this. If a history stops resuming, re-record it from the case's `turns.md` with step 6's commands.
- A re-recorded history no longer tests what its case needs. `turns.md` keeps only the user's turns, and Claude's replies differ on every recording, so a case that relies on a particular idea from Claude (`attributes-ideas`, `unanswered-suggestion-stays-open`, `records-final-position`) can lose it (spec design: multi-turn cases). A re-recorded history is read against its case's graders and shown to the operator before use, exactly like a first recording (operator decision, 2026-11-04).
- Absolute paths differ on macOS: `git rev-parse --show-toplevel` gives `/private/tmp/…` where `pwd` may give `/tmp/…` (spec R5, R20). A grader can't know the run's directory, so the reply check matches an absolute path ending `/.handoff/<YYYYMMDD-HHMM>-<slug>.md` (`regex` on `last_message`) without fixing its prefix, and the file's location is checked with `file_exists`, relative to the run's directory.
- A history carries something it shouldn't: a real secret, a personal path, or the turns of the session that recorded it (spec R19). Step 6 records in a neutral scratch directory and reads every history before it is kept, and the operator sees each one before the runs.
- The skill fails to tell Claude's ideas from the user's decisions, which is the main point of the skill (spec R12, R13). Three cases target this (`attributes-ideas`, `unanswered-suggestion-stays-open`, `records-final-position`), and the reviewer can check each verdict against `input--history.jsonl`.
- The model writes the secret anyway, or a fragment of it (spec R19). The `secret-omitted` grader is a `tool_used` grader on Write, with `input_match` set to the whole fake key or its distinctive middle part and `min: 0, max: 0, arm: both`, not an LLM judgement. It sees only this run's Write calls, so the key in the resumed history cannot fail it.
- The handoff file's name holds a timestamp, and `{source: file, path}` takes no globs, so no grader can read the file by path (spec R7, R10). Content checks match the run's Write call instead (`tool_used` with `input_match`, or an `llm` grader on the trace). Step 3 checks how that input is serialized on the first run.
- A placed file that the run changes never appears in `files` or `file_exists`, which list only created files (spec R6, R9, R21). Unchanged placed files are checked by content with `{source: file, path}`. Writes outside `.handoff/` are checked with `tool_used` on Write (a `file_path` outside `.handoff/`, `max: 0`), on Edit (`max: 0`), and on Bash (only `git rev-parse` and `date`).
- A run changes the recorded history it resumes, so every later run starts from a different conversation (spec design: multi-turn cases). Step 7 resumes a copy and checks the case folder's file afterwards; step 3 checks whether `claude plugin eval` leaves the file alone.
- A history or a run carries the operator's own context: global CLAUDE.md, memory, plugins, email (spec R19). Step 6 records, and step 7 runs, under a fresh `CLAUDE_CONFIG_DIR`, and step 6 reads each history for these before keeping it.
- Headless runs deny tools that were not granted, so an ungranted Write makes every run fail (spec R21, R22). Steps 7 and 10 grant Write and only the Bash commands R22 allows; a denied call in a trace is a finding, not a harness fault.
- The eval report, which carries every history and output, is published to claude.ai by default. `make evals` always passes `--no-publish`.
- `claude plugin eval` writes a session log, `<session-id>.jsonl`, next to each case's `history.jsonl` and appends to it on every run; it holds the operator's username, machine paths and raw API requests. `plugins/workflow/.gitignore` ignores `evals/*/*/*-*-*-*-*.jsonl`, so these logs are never committed (operator decision, 2026-11-05).
- The skill misreads a Read error (for example, taking a permission error for a missing file), and so either points to init when the file is there, or writes without it, or overwrites a handoff file (spec R6, R9, R22). Step 3 checks Read on present, missing and dotfile paths. Write's own read-before-overwrite guard does not help here: reading a taken name with `limit: 1` satisfies it, so an overwrite of that file would go through. `no-overwrite` catches an overwrite; `missing-gitignore-points-to-init`, and every other case (each places the file), catch a wrong gitignore answer.
- `init` creates `.handoff/.gitignore` somewhere other than where `/handoff` looks, so `/handoff` keeps pointing to init after it has run (spec R5, R6). Step 3 checks `init`'s SKILL.md against R5 before drafting.
- `no-overwrite` can miss its collision when the minute changes between setup and the run. Accepted; the case is rerun (spec design: test cases, operator decision 2026-11-04).
- `outside-git-repo` silently runs inside a repo if the scratch or scaffold directory sits under one (spec R5). Step 3 checks where scaffold directories live, and the case's grader checks that the handoff file is created under the run's own `.handoff/`.
- No baseline means no measured improvement over doing nothing (spec design: no baseline runs). Accepted under the command-only exemption; the evidence is the with-skill runs and the operator's review.
- `claude plugin eval` would add a no-plugin arm to `nothing-to-hand-off`, the one case without a history. `make evals` passes `--ablation none` for a command-only skill, consistent with the exemption.
- Developing in this repo, `/handoff` looks in `ae-skills/.handoff/`, since the git root is `ae-skills/` (spec design: finding the directory). It writes nothing there until `/workflow:init` has been run in `ae-skills/`, and then `.handoff/.gitignore` keeps the files out of commits; step 14 checks `git status`.
- A step-7 run made with `claude -p` differs from an interactive session, for example in how the reply is captured (spec R20). The `claude plugin eval` run in step 10 runs the same cases through the official runner as a cross-check.
